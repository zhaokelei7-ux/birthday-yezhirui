# 叶智睿的生日祝福 — 设计文档

日期：2026-11-18
状态：已与用户确认（单页互动网页、纯静态 SVG、GitHub Pages 部署）

## 1. 目标

做一份可以发链接给寿星**叶智睿**的生日祝福网页。核心体验：

- 一个俯视的三层生日蛋糕，共 **28 块**，初始全部灰暗、只显示姓名。
- 28 块对应 28 位送祝福的人：**20 位同学 + 7 位志工 + 1 位班主任**。
- 点击某人的名字，播放 TA 录好的「生日快乐」语音；语音播完后，该块被点亮，中央卡片显示 TA 写给叶智睿的一句文字祝福。
- 28 块全部点亮后，烟花绽放，出现终极大祝福。

寿星叶智睿本人不在名单中、不占扇区。

## 2. 非目标

- 不做后台、评论、留言提交、账号系统。
- 不做照片墙、背景音乐、多语言。
- 不做原生 App；只交付一个网页链接。
- 不编造具体共同经历；祝福文案保持真诚、通用。

## 4. 视觉设计

整体是温暖的夜色生日场景，全部由代码绘制，无图片、无外部字体依赖。

- 背景：深可可色径向渐变（#17110f → #241a15），叠加细小星点。
- 蛋糕：俯视圆形，奶油色底胚 + 柔和投影；外圈、中圈、中心三层。
- 未点亮扇区：低饱和灰紫（#4b4654），描边 #5f596b，姓名文字 #b9b3c6。
- 点亮扇区：暖金/奶油色（#ffe3aa 过渡到 #fff4de），外发光 #ffc95c，姓名改为深棕 #3a2a12，边缘升起一小簇火苗。
- 分组色仅作点亮后的点缀：
  - 冲刺队 #ff8a65、战神队 #ffd166、超越队 #7fd1ae、力量队 #7fb7ff
  - 志工团 #ff9fb2、班主任 #ffd75e
- 字体：`system-ui, "PingFang SC", "Microsoft YaHei", sans-serif`。
- 布局：手机竖屏优先；桌面端蛋糕最大宽度约 720px，垂直居中；页面无横向滚动。

### 蛋糕几何

使用 SVG，`viewBox="0 0 1000 1000"`，圆心 (500, 500)。

- 外圈：半径 470 → 340，20 块，每块 18°，从正上方开始顺时针。四个队各连续 5 块（90°）。
- 队名不占用环外空间，统一放在蛋糕下方的图例中：冲刺橙、战神金、超越绿、力量蓝、志工粉、班主任金。图例只作视觉说明，不可点击。
- 中圈：半径 340 → 220，7 块，每块 360/7°，起始角相对外圈错开半个扇区，避免切缝对齐。
- 中心：半径 220 的整圆，班主任卢钰涵。
- 姓名放在扇区中径处，沿半径方向排布；左半边的文字旋转 180° 保持可读。
- 手机 375px 宽时，外圈每块点击区域约 47×49px，满足最小 44px 触控目标。

## 5. 交互流程

### 首屏

- 标题：「叶智睿，生日快乐」。
- 进度：`0 / 28`。
- 提示：「点击任意一块蛋糕，听 TA 对你说生日快乐」。
- 蛋糕整体灰暗，28 个姓名可点击。

### 点击未点亮的人

1. 该扇区轻微向外弹出并高亮，出现声波动画。
2. 播放此人语音；全局进入 `playing` 状态，其他扇区变淡且点击暂不响应，避免串音。
3. 中央卡片显示：「正在收听 · 宋书涵」+ 播放进度条 + 关闭按钮。
4. 语音自然播放结束：
   - 该扇区点亮并升起火苗，进度 +1；
   - 卡片切换为祝福视图：姓名、分组、一句祝福全文、「重播语音」按钮。
5. 播放期间点击关闭：停止播放，不点亮，回到 `idle`。
6. 语音加载失败或超时（已知时长则为其 + 5 秒；无时长信息时统一 15 秒）：
   - 卡片直接显示祝福，并标注「语音暂缺」；
   - 该扇区仍点亮，流程不中断。

### 点击已点亮的人

- 重新打开祝福卡片，可重播语音；不会熄灭、不重复计数。

### 全部点亮

- 第 28 块点亮后，卡片自动收起。
- 28 簇火苗同时亮起，canvas 烟花绽放约 8 秒。
- 大标题：「叶智睿，生日快乐！」；副标题：「28 份祝福，全部点亮」。
- 结局覆盖层提供「再看一次烟花」按钮，可随时关闭。
- 仅在本次会话中第 28 块刚刚点亮的那一刻自动触发烟花；刷新后若已是全部点亮，则蛋糕保持点亮、显示标题与「再看一次烟花」按钮，不自动重放。

### 持久化与重置

- `localStorage` 键：`yzr-birthday-lit-v1`，保存已点亮姓名数组。
- 右上角「重新开始」按钮，二次确认后清空进度。
- 无痕模式或 localStorage 不可用时，仅本次会话生效，不影响使用。

## 6. 数据模型

`data/people.json` 保存 28 条记录（JSON 便于浏览器、Python 校验脚本和 Node 测试共用）：

```json
[
  {
    "name": "宋书涵",
    "group": "classmate",
    "team": "冲刺队",
    "blessing": "叶智睿，生日快乐！愿你的每一次冲刺，都奔向热爱。"
  }
]
```

`group` 取值：`classmate`（同学）、`volunteer`（志工）、`teacher`（班主任）。

- 数组顺序即蛋糕排布顺序：外圈按冲刺 → 战神 → 超越 → 力量各 5 人，中圈 7 位志工，中心班主任。
- `data/audio-manifest.json` 由转换脚本生成：

```json
{
  "宋书涵": { "file": "audio/p01.mp3", "duration": 2.8 },
  "卢冲":   { "file": "audio/p02.mp3", "duration": 3.4 }
}
```

- 页面用相对路径加载数据与音频（`./data/...`、`./audio/...`），保证部署在 GitHub Pages 子路径下也能工作。
- 未出现在 manifest 中的人：卡片显示「语音暂缺」，仍可点亮。

## 7. 音频处理

语音来源为**用户自己录制的音频文件**（手机录音、电脑录音均可），不走微信语音。

- 原始文件放在 `audio-src/<姓名>.<扩展名>`，支持的扩展名：`.mp3`、`.m4a`、`.aac`、`.wav`、`.ogg`、`.flac`、`.amr`。文件名只写姓名，例如 `audio-src/宋书涵.m4a`。
- 处理脚本 `scripts/convert_audio.py`：
  1. 按 `PEOPLE` 顺序在 `audio-src/` 中查找同名音频（不区分大小写，允许多种扩展名）；
  2. 用 ffmpeg（通过 `imageio-ffmpeg` 提供的二进制）统一转码为 `mp3`：单声道、16kHz、64kbps，并做响度归一化（`loudnorm=I=-16:TP=-1.5:LRA=11`），保证 28 段音量一致；
  3. 输出 `audio/p01.mp3` … `audio/p28.mp3`，用编号命名，避免中文 URL 编码问题，也不在文件名中暴露姓名；
  4. 生成 `data/audio-manifest.json`，以姓名为键记录文件路径与时长；
  5. 打印缺失名单和每段时长，方便检查有没有漏录或过短。
- 如果 ffmpeg 暂时不可用，脚本先直接复制浏览器可播的源文件到 `audio/pXX.<原扩展名>`，并在 manifest 中记录实际扩展名，保证页面能用；之后补装 ffmpeg 再统一转码。
- Python 环境：`/d/miniconda/envs/finpy/python.exe`。首次运行需要安装 `imageio-ffmpeg`（联网，自带 ffmpeg 二进制，无需系统安装 ffmpeg）。
- README 写明录音要求：安静环境、离麦克风 10–20cm、每段 2–15 秒、开头可直接说「叶智睿，生日快乐」，文件按姓名命名放进 `audio-src/`。
- 音频文件总量预计小于 5MB，按需加载，不影响首屏。

## 8. 错误处理

| 场景 | 行为 |
|---|---|
| 音频文件缺失 | 卡片标注「语音暂缺」，仍展示祝福并点亮该块 |
| 音频加载失败/格式错误 | 捕获 `error` 事件，同上 |
| 音频播放卡住 | 超过时长 + 5 秒后按失败处理，允许关闭 |
| 非安全上下文或浏览器拦截自动播放 | 播放由点击触发，不受影响；若 `play()` 被拒绝，按失败处理并给出提示 |
| localStorage 不可用 | 静默降级为会话内状态 |
| 数据条数不为 28 或分组数量不符 | 构建前校验脚本直接报错，不部署 |
| 缺少 SVG/JS 支持 | 页面显示纯文字降级提示（现代浏览器均支持，仅作兜底） |

## 9. 无障碍与动效

- 每块扇区是 `role="button"`、`tabindex="0"`，`aria-label` 含姓名、分组和状态；Enter/Space 可触发。
- 中央卡片 `role="dialog"`，打开时焦点移入，Esc 关闭；祝福文本用 `aria-live="polite"`。
- 焦点样式清晰可见。
- 尊重 `prefers-reduced-motion`：关闭弹出、烟花、火苗闪烁等动效，只保留状态变化。
